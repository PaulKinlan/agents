### Which fact was false, and which decision depends on it

One measured fake HOME/state file, a real live shared `host_pid`, a fresh `last_event_at`, and **no per-lane socket** gives opposite answers: `lanes.sh status des-x` says `stopped` (rc 0); `inbox/status.mjs status({vm})` says `running:true, pi_alive:true, intercom:"idle", last_event_min:0` (rc 0). The whole-value comparison fails in `/tmp/agents-f6du-hs4i-red-first.log`. `lanes.sh:106–124` tests SDK `host_pid > 1`, process liveness, and a **connectable lane socket**; `status.mjs:65–66` tested only the shared host PID and `:117` hardcoded `pi_alive=true` for SDK. The latter is a false positive for **this lane's session**, not a more timely reading.

The SDK producer sets `host_pid=process.pid` for every lane (`sdk-host/host.mjs:85`), listens on that lane's socket only after building its session (`:118–126`, `:251–270`), and unlinks that socket **before** clearing/saving `host_pid` on stop (`:273–309`). Restart/fresh need not set the parked `.stop` marker, so a live host with stale per-lane state is a real transition, not a fabricated clock edge. `last_event_min` is a separate *progress/recency* fact: it must not decide session presence, as the deployed `tests/lanes.test.sh` section 11 already pins for quiet live lanes.

`status.mjs` feeds the watchdog's `down`→`startLanes` rule (`watchdog.mjs:209–210`) and `running`/`pi_alive` gates for health, stuck detection and orphan dispatch (`:220–251`, `:582–585`), plus the dashboard's dot (`dashboard/app.js:154,173`). With the old false positive, the watchdog can miss a missing lane while the dashboard shows it healthy. Autopilot reads `lanes.sh list` instead (`remote/autopilot.sh:11`), so it can decline to dispatch on precisely the lane that the watchdog calls running. **Reviewer finding agents-05rh** exposed the opposite mistake in the first artifact: when a failed-over SDK lane's socket was absent, returning `null` from `hostState()` lost its stored `stuck` reason and `model`, so the status view hid the failure while correctly reporting `running:false`.

This patch separates the **parsed SDK state** from the **per-lane session witness**. A valid shared PID **and** a real connectable per-lane Unix listener are required for `running`, `pi_alive`, `busy`, `intercom`, active `session_min` and `turn_age_min`; an absent socket does NOT discard `stuck`, `model` or the historical last-event diagnostic from that state file. Malformed/non-object state still fails closed without crashing the status reader, and the non-SDK path preserves its old PID/metadata behavior. The Node socket probe treats a full-backlog/timeout listener as live, matching `lanes.sh sock_live`'s rc 124 rule; missing/refused/stale socket paths are not live. It does not invoke another liveness CLI or read the activity clock into liveness. An explicit 1-second deadline (including a connect that never settles) is the saturated-listener upper bound **per SDK lane**; ordinary Unix-local connects return immediately. This ceiling must be considered if many lane listeners saturate simultaneously; no general throughput claim is made from a clean fake-HOME test.

### Explicit residual: the reaper is a THIRD reader

`remote/reaper.mjs:117` independently calls every lane with a live `state.host_pid` *live*, even in SDK mode where that PID is shared. At `:180` this flips a detached job's `orphan` to false; orphan-browser and CPU/runtime rules subsequently change. That is not fixed by changing `status.mjs`. A deterministic **dry-run only** probe with a synthetic 12-minute orphan-browser process-table row for a real inert PID tagged `FLEET_LANE=des-x`, and a stale SDK state with live host PID/no socket, reports **0 would be killed**. Removing only that stale state reports **1 would be killed: orphaned browser (12 min)** (`/tmp/agents-f6du-hs4i-reaper-probe.log`, script alongside it). No real browser, kill or message delivery occurred. This is a separate destructive consumer/action contract, tracked as **agents-j8f4** (its own artifact and kill/no-kill tests, currently IN_REVIEW). The status correction here retains `stuck` without declaring the lane present; it neither changes nor clears the reaper's own review. Do not weaken `lanes.sh` to agree with the original host-only readers, and do not claim fleet-wide convergence from one artifact.
