# Software Factory site design (Opus design pass)

This is the design deliverable for `https://paulkinlan.github.io/agents/`. The visual and interaction design of the six pages was authored by Claude Opus 5.5 (`claude-opus-5-5`), as the brief requires. It replaces an earlier interim pass by a stand-in model; the information architecture and generator contract below are carried over from that pass, while the visual system, components, mobile behaviour and contrast record are this pass's work. `tools/gen_site.py` refills the marked regions of the six pages in `docs/` from the repository's own declarations, and CI fails if the committed output is stale. Everything outside those regions is hand-authored. No JavaScript, build framework, external font, CDN or runtime API is required, and the pages render correctly from `file://` with the network off.

## Information architecture

| Page | Reader's question | Source of dynamic content |
|---|---|---|
| `index.html` | What is it, why use it, how do I start? | Editorial + generated quickstart commands; review prose against README and AGENTS.md on each change |
| `install.html` | What do I need and how do I install locally/in CI? | Generated factual blocks from README, AGENTS.md, argparse, `docs/INTEGRATION.md`, action metadata; editorial headings outside regions |
| `use.html` | How do I run a station/Line and where do results go? | Editorial + generated `cli-reference` from actual argparse command tree |
| `stations.html` | Which stations exist and what may they require? | Generated `stations` from `agents/*/agent.yaml` |
| `lines.html` | Which Lines exist, in what order, and when do they stop? | Generated `lines` from `lines/*.yaml` |
| `help.html` | Why these safety constraints and what do statuses mean? | Editorial; review against README, AGENTS.md, THREAT_MODEL.md |

Navigation is intentionally six top-level destinations, with short in-page navigation only on long-form pages. Every link is either within `docs/` or a source repository link. The root Pages URL is repository-scoped; all asset and internal paths are relative. `index.html` is the default Pages entry; other pages are flat files. No favicon is requested because none is shipped. This replaces the old root-absolute `/css/...`, `/` and non-existent `/favicon.png` references. No source file paths under registered targets are published.

## Visual system (Opus pass)

**Files and layers.** `css/projects.css` owns the palette and the `@layer reset, base, layout, components` order; `css/product.css` owns buttons and generic content; both are unchanged in this pass. All documentation styling lives in `css/factory.css`, which only *adds* tokens: `--radius-sm`, `--doc-hairline #24314d` (decorative internal dividers only), solid class tints `--tint-observer #1b2b4a`, `--tint-proposer #15332d`, `--tint-optimizer #2a1f48`, `--warn #ffd28a`, `--mono`, and a type ramp `--step-title`, `--step-title-home`, `--step-h2`, `--step-h3`. Existing custom properties keep their names and meanings.

**What changed, and why.**

- *Hierarchy.* There is now one display size per page. The interior page title dropped from `clamp(2.5rem, 5vw, 4.7rem)` to `clamp(2rem, 1.35rem + 2.6vw, 3.25rem)`, with only the home page using a larger `--step-title-home`. Section headings sit on a short, even ramp (`h2` ≤ 1.8rem, `h3` 1.15rem) instead of jumping from 4.7rem to 2.5rem to 1.25rem. Kickers and `dt` labels share one small uppercase style.
- *Hero.* The old hero combined large `h1` margins, `margin-block-end: 2.25rem` on the lede, and up to 4.25rem of padding, which left a dead band under every title. The hero is now compact: the eyebrow, title and lede are stacked tightly, the lede has no trailing margin, and padding tops out at 3rem. On the home page, the second "hero" that sat inside the content column was merged into the real hero, which now holds the CTAs and the run-at-a-glance rail. The page no longer has two competing heroes.
- *Surface ramp.* Depth is used on purpose: page `#0b1020`, then card surface `#121a2e`, then raised `#17233c` for the parts of a card that hold metadata or policy (station capability band, Line Andon policy band, metadata chips, inline code), then `--code-bg #060913` for code. The `#5c6b87` boundary is kept on cards and chips (3.22:1 against the surface). Purely decorative internal rules use the quieter `--doc-hairline`, so dividers stop competing with card edges.
- *Rhythm.* Section padding is a single `--space-5` step with a hairline between sections, prose is capped at 70ch, and the last section on a page has no trailing rule.

**Components.**

- *Header nav.* The current page is shown by bold weight, a quiet raised background and a 2px accent underline. It used to be a filled accent pill, which dominated on mobile. The six links sit in a `<ul>` inside `<nav aria-label="Site"><details class="site-menu">`, with a `<summary>` that reads `Menu · <current page>` (the dot is `aria-hidden`). At **≥ 48rem** the summary is `display: none` and the closed content slot is forced open with `.site-menu::details-content { display: block; content-visibility: visible }`. Author declarations beat the UA rule that hides closed `<details>` content, so the result is the same single right-aligned row as before. Below 48rem the summary is a full-width, 44px bar with a CSS chevron, and opening it reveals a two-column panel of 44px links *in flow*: it pushes content down, does not overlay it, and never scrolls sideways. The wide-screen override sits inside `@supports selector(::details-content)` (Chrome 131+, Safari 18.4+, Firefox 143+). Older engines cannot un-hide closed `<details>` content, so they keep a working native disclosure at every width instead of losing the nav.
- *Station card.* The station name is set in monospace because it is a CLI identifier. Chips come next: the class chip is tinted and coloured by class, and the plane and containment chips carry visible `plane` / `tier` labels supplied by CSS, because the generator emits bare values. Chips are `.72rem` with `.1rem .45rem` padding and a `.3rem` gap. That is sized so the longest set (`optimizer` · `plane ci, local` · `tier t2-local`, about 300px) fits on one line in the ≈ 360px content box of a 3-column card at 1440px. At 1440px chip rows therefore no longer wrap on some cards and not on others. In single-column cards below about 360px they still wrap, the same way on every card. A legend on the stations page explains the three classes in words. Its swatches use the *same* rule as the card chips (one shared `.meta li, .station-legend dt` box, plus the class chip's 700 weight, `currentColor` border, accent colour and solid tint), so the two cannot drift. The Capability/Requires `dl` sits in a raised band pinned to the foot of the card, so the bands line up across a grid row. The grid is `auto-fill, minmax(19rem, 1fr)`, which gives three columns at 1440px and one at 390px. A card whose heading is the URL target (reached from a Line) gets an accent outline.
- *Line card.* The itinerary is a zero-padded, numbered list of station links in monospace, two columns when there is room. The Andon policy sits in a raised band at the foot.
- *CLI reference.* Each generated `.command` is a card. The heading reads `./factory <name>`, with the `./factory` prefix added in muted CSS-generated text. The description is muted, and the exact parser usage runs edge to edge in a code panel below it.
- *Code blocks.* Above 48rem, `pre` blocks keep `white-space: pre` and scroll horizontally inside their own box (`max-inline-size: 100%`), because long `usage:` lines read better unwrapped. The scroll affordance is a pair of CSS-only edge shadows (`background-attachment: local` covers over `scroll` shadows), so a shadow appears only on a side where content is clipped. Thin scrollbar. **At ≤ 48rem every `pre` switches to `white-space: pre-wrap; overflow-wrap: anywhere`.** A command line wraps at spaces, or mid-token if it has to, so it is fully readable with no sideways gesture. Nothing overflows, so the edge shadows cancel out and the block is not a scroller. There is no hanging indent, because `text-indent: each-line hanging` is not reliable in Chromium; wrapped continuations start at the left padding. Inline `code` also gets `overflow-wrap: anywhere` at that width. A focused `pre` (a scroller at wide widths) draws the same 3px accent ring as links, inset (`outline-offset: -3px`) so neither its own overflow nor the `overflow: hidden` CLI card can clip it. A `pre` that ends a `.command` card takes the card's inner bottom radius so the ring is not cut at the corners.
- *Pipeline flow.* Three numbered stages joined by a drawn chevron connector. It turns vertical in narrow containers, and the chevron rotates to point down.
- *Callouts.* The coloured edge carries the tone, and the bold first line always names it in words. Warning titles use `--warn`.
- *FAQ.* Native `<details>` with full-width summaries at least 44px tall and an accent marker. The open state is shown by colour plus the native marker.
- *State vocabulary.* On the help page this is a list: one badge and one sentence per line.

**Mobile.** Below 48rem the header stacks: identity on the first row, then the full-width `Menu · <page>` disclosure bar described above. The previous design was one sideways-scrolling nav row with a negative inline margin. It was removed because it widened the page (measured `scrollWidth` 403–409 against `clientWidth` 390 at 390px on all six pages, worse at 320px) and hid "Lines"/"Help" off-screen with no affordance. At ≤ 48rem code blocks wrap (see *Code blocks*). The local "On this page" nav (≤ 48rem) collapses from a tall list into one wrapping row of pill links. Cards, callouts and code panels trim their inline padding to 1rem. Station and Line grids drop to one column through container queries, and the hero grid stacks below 52rem.

## Accessibility

- Semantic `header/nav/main/footer`, one `h1` per page, ordered lists for sequences, and `<details>` for the FAQ. There are no icon-only controls.
- Every link, summary and focusable `pre` gets a 3px accent `:focus-visible` outline. Header nav links and `pre` blocks draw it inset (`outline-offset: -3px`) so no parent clip can cut it. The skip link lands on `main#content`.
- The header nav is a no-JavaScript `<details>` disclosure below 48rem. Its `summary` is the native disclosure button (expanded/collapsed state is exposed by the browser) and it is 44px tall. Esc does not close it and it does not close on outside click; that would need script. Browser find-in-page opens it automatically.
- `prefers-reduced-motion` disables smooth scrolling and transitions.
- In `forced-colors`, card, chip, legend, side-nav and connector boundaries become `CanvasText`, and the current-page underline uses `Highlight`. Because the current page is also bold and underlined, it never relies on background colour alone.
- Layout target: `document.documentElement.scrollWidth <= clientWidth` at 320, 390 and 1440px on all six pages, and every header link reachable without a sideways gesture. Code wraps at ≤ 48rem, so nothing on a narrow page needs horizontal scrolling.
- Rendering record **before** this pass's fix: at 390px `scrollWidth` was 403–409 against `clientWidth` 390 on all six pages, and worse at 320px; hiding `header.site-header` removed all of the overflow, so the old sideways-scrolling nav row (negative inline margin) was the only cause. That render also showed code clipped mid-command at 390px (`use.html`, the index quickstart) and chip rows wrapping inconsistently at 1440px.
- Rendering record **after** the fix, measured with headless Chrome 155.0.8059.39 over the committed tree at 1440, 390 and 320px on all six pages (full-page CDP captures, `Emulation.setDeviceMetricsOverride`, `mobile: false`):
  - `document.documentElement.scrollWidth` equals `clientWidth` at **every** page and width — no page-level horizontal overflow anywhere. The full-page capture at a 390px viewport is now exactly 390px wide (it was 405–409px before), and index at 320px is exactly 320px wide.
  - Internally scrolling code blocks at 390px and 320px: **zero**. They wrap, so no command needs a sideways gesture; at 1440px `use.html` keeps its three horizontally scrolling usage panels, by design.
  - Header nav at ≥48rem: the summary is `display: none` and the six links are one row. At 390/320px the summary `Menu · <page>` is shown, the panel starts closed (`::details-content` computes `content-visibility: hidden` with a zero block size), and keyboard order is skip link → identity → `Menu` → the rest of the page, i.e. the closed links are not tab stops; opening the panel puts all six links fully inside the viewport.
  - WCAG contrast: **0** violations across the 18 page/width combinations, measured on computed styles against composited ancestor backgrounds.
  - Deterministic factory pre-pass `agents/accessibility/scripts/audit_a11y.py --target-dir docs`: **0** candidate violations over the six pages.
  - Emulated media: with `prefers-reduced-motion: reduce` the computed `scroll-behavior` is `auto` and transition durations collapse to `1e-05s`; with `forced-colors: active` card, callout, command, flow and preview borders compute to `CanvasText` and the current-page underline to `Highlight`.
  - Evidence artefacts (not committed): full-page captures and the audit JSON are under `.5qe-design-review/after/` and `/tmp/5qe-design/` in the authoring worktree.
- Known limitation: at wide widths `pre` blocks still scroll horizontally, and whether they can be scrolled from the keyboard depends on the browser focusing scroll containers natively (current Firefox and Chromium do). Wrapping removes the need only at ≤ 48rem, where nothing scrolls.
- Known limitation: in engines without `::details-content`, the header shows the `Menu` disclosure at wide widths too, instead of the single row of links.
- Known limitation: the closed `Menu` bar is an in-flow disclosure - it is dismissed with a second activation of `Menu`; click-outside and Escape do not close it, which would need JavaScript.

## Generator contract (next implementation)

**Only replace the content between exact comment pairs**, retaining the marker comments themselves. Shorthand `GENERATED:<name>` in the table means the exact `<!-- BEGIN GENERATED:<name> -->` … `<!-- END GENERATED:<name> -->` pair. No nesting or duplicate names within a page. Editorial text outside regions is human-owned, including the context heading before each region, intro prose, operational warnings and links. Do not regenerate the whole page from README markdown. Treat input as untrusted text: HTML-escape text and attribute values; whitelist generated fragment identifiers to slugs `[a-z0-9-]+`; validate relative links against output filenames; do not interpolate scanner output, report data, paths from target manifests, secrets, or runtime command output other than the public CLI help/list catalog. Sort station and Line records by name, preserve station order **within** Lines. Deterministic output and idempotent replacement; refuse duplicate/missing markers, missing referenced station, unknown required fields or invalid enum. Regenerate all three regions in the same build, validate, then publish atomically.

Station IDs in these examples are `station-<name>`; Line IDs are `line-<name>`; CLI IDs are `cmd-<name>`. Preserve these public anchors and internal link targets on regeneration. Source YAML is a declaration, not observed runtime capability. The count 22 and 2 is snapshot-only: do not hardcode it in future generator templates. The sample CLI synopsis intentionally omits some help detail; the generator should extract the parser rather than scraping this HTML. Use `README.md`, `AGENTS.md` and `docs/INTEGRATION.md` only as public documentation inputs for safe facts and editorial review, never as unfiltered HTML. For operational claims not machine-extractable, regenerate only after comparing to runtime behavior; fail when sources conflict. `use.html`'s two hand-authored command examples and help copy must be validated against the generated catalog and actual sink behavior on every build; do not silently leave stale names in prose. The current README/integration guide contain historical sink descriptions in places: the actual `factory` and current AGENTS.md rule file/beads for findings, with GitHub Issues only as input for issue-triage/promotion. Resolve future source disagreements by inspecting code and escalating; do not silently publish conflicting claims.

## Publish/review checklist for the next implementer

- Generate from the current checkout, not an old branch or a locally cached target inventory. Commit generated pages and reject stale output in CI by regeneration + clean diff; GitHub Pages deploy from `docs/` on reviewed main. Do not publish private artifacts or runtime target metadata.
- Validate marker uniqueness and exact fact counts from source; validate every internal href, CSS response at the repo-scoped Pages URL, headings and keyboard navigation. Render actual browser screenshots at wide/narrow widths and independently review before push.
- Check `./factory --help` and nested help against CLI region; compare `factory list` station names and Line YAML station references; inspect env-failure, sink and visibility copy after related code changes.
