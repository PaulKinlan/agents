The Software Factory

A schedulable fleet of software-development-lifecycle (SDLC) agents that run locally under your existing developer session authentication (pi, claude, antigravity, deepseek) and in CI on GitHub Actions.

Get Started Integration Guide View on GitHub Architecture

The Factory in Action: Running deterministic gitleaks pre-pass, session-auth AI adversarial verification, and routing deduplicated findings to local Beads.

Deterministic Scanners Enumerate.
AI Models Triage, Synthesize, and Judge.

Most agent systems either burn expensive token budgets reading thousands of irrelevant files, or run brittle heuristic scripts that produce noisy false positives. The Software Factory combines fast deterministic discovery with targeted AI verification.

⚡ Deterministic-First

Native tools (gitleaks, npm audit, AST parsers, custom regex harnesses) extract candidate locations in milliseconds. AI models never do work a static tool does faster, cheaper, and reliably.

🤖 Agent-First CLI (--agent)

AI coding agents can run ./factory --agent or ./factory integrate to receive machine-actionable instructions and copy-pasteable workflow recipes directly on stdout.

🔑 Reuses Existing Session Auth

No new third-party accounts or subscriptions needed. Runs locally using your active CLI session tokens (pi, claude, antigravity, deepseek) and headlessly in CI with GitHub Secrets.

🚀 CI Composite Action

The official composite action (paulkinlan/agents/.github/actions/factory) runs in GitHub Actions with credential-blanking setup, step-summary redaction, and private delta artifacts.

🛡️ Disprove-Only Verification

Discovery and verification operate in separate sessions. Discovery optimizes for recall; verification runs in a fresh, isolated session prompted strictly to disprove findings before filing.

🎯 Stable Fingerprinting

Findings are keyed by sha256(agent:rule:path:snippet), deliberately omitting line numbers. Refactoring code around a finding preserves its identity and avoids duplicate alerts.

📦 Pluggable Issue Sinks

Verified findings route directly to whatever issue tracking system your repository uses: local Beads (.beads), public GitHub Issues, or private markdown delta reports.

🔒 Public Disclosure Guard

High and critical security vulnerabilities are never posted directly to public issue trackers. They are safely isolated into encrypted local files or draft security advisories.

Architecture & Pipeline

Every agent run follows a clean, five-stage lifecycle executed by the factory dispatcher:

1. Trigger
Manual CLI invocation (./factory run, ./factory line, ./factory hillclimb), scheduled daemon (launchd / systemd), or GitHub Actions CI workflow dispatch.
2. Enumerate
Deterministic pre-pass scans target repository and inspects THREAT_MODEL.md to produce structured candidate JSON. Tools: gitleaks, npm audit, custom Python AST scanners (<150ms pre-commit gate)
3. Triage & Judge
AI engine adapter (pi, claude, antigravity, deepseek) executes the agent's SKILL.md against candidate findings. Fresh-context verification prompt tests for false positives
4. Dedupe
Findings store computes stable SHA-256 fingerprints, updates lifecycle states (new → accepted | wontfix → fixed → regressed), and ignores known noise.
5. Sink
Output lands in local Beads issue database (bd), GitHub Issues via gh CLI, or local markdown reports (guarded by public disclosure embargo).

Quickstart & Setup

Set up the factory locally, in CI, or as an agent skill in less than two minutes.

1

Clone and install

Ensure Python 3.9+ and at least one coding CLI (pi, claude, antigravity, or deepseek) is available.

git clone https://github.com/PaulKinlan/agents.git
cd agents
./install.sh
2

Query Agent Guidance (--agent)

Inspect machine-actionable instructions and copy-pasteable CI/CD recipes:

# Print full agent integration guide
./factory --agent

# Or print specific GitHub Actions workflow templates
./factory integrate --section github-actions
3

Run an agent or factory line

Run against any registered target in targets/ or against any local directory:

# Run secret scan on a project
./factory run secret-scan --target /path/to/my-web-app

# Run a composed Factory Line with automatic Andon Cord halt
./factory line project-audit --target /path/to/my-web-app

# Run Class C performance hill-climbing
./factory hillclimb --target /path/to/my-web-app --metric perf_hazard_score --goal 0
4

Run in GitHub Actions CI

Add the official composite action to any repository workflow (.github/workflows/security.yml):

- uses: paulkinlan/agents/.github/actions/factory@main
  with:
    agent: secret-scan
    target: .
    model_api_key: ${{ secrets.GEMINI_API_KEY }}

See docs/INTEGRATION.md for complete PR gate, nightly audit, and issue triage recipes.

5

Schedule recurring sweeps & pre-commit hooks

Install sub-second pre-commit hooks and daily macOS launchd / Linux systemd background audits:

# Install sub-150ms deterministic pre-commit hook (Rule 8 compliant)
./factory hook install --all

# Generate and install daily morning briefing schedules
./factory schedule generate && ./factory schedule install --all
